4.2 Uso de bases de datos relacionales y NoSQL

No existe una única tecnología óptima para todos los casos. Las bases relacionales destacan en integridad y consultas complejas; las NoSQL en flexibilidad de esquema, escalado horizontal y ciertos patrones de acceso.

1. Comparativa rápida

Aspecto Relacional (SQL) NoSQL (ej. MongoDB)
Modelo Tablas, filas, columnas Documentos, clave-valor, grafos, columnas
Esquema Rígido (DDL previo) Flexible / dinámico
Transacciones ACID fuerte Varía (MongoDB soporta multi-documento ACID)
Escalado Principalmente vertical (+ réplicas) Diseñado para horizontal (sharding)
Consultas SQL potente (JOINs, ventanas) API de agregación / consultas por documento
Casos ideales ERP, finanzas, sistemas transaccionales Contenido, IoT, catálogos, perfiles de usuario

2. Bases relacionales desde Python

SQLite (ideal para práctica y prototipos)

import sqlite3
import pandas as pd

conn = sqlite3.connect('tienda.db')

# Ejecutar SQL
conn.execute('''
CREATE TABLE IF NOT EXISTS clientes (
    cliente_id INTEGER PRIMARY KEY,
    nombre TEXT NOT NULL,
    ciudad TEXT
)
''')
conn.commit()

# Leer a DataFrame
df = pd.read_sql_query('SELECT * FROM clientes', conn)
conn.close()

PostgreSQL con psycopg2 / SQLAlchemy

# pip install psycopg2-binary sqlalchemy
from sqlalchemy import create_engine, text
import pandas as pd

engine = create_engine(
    'postgresql+psycopg2://usuario:password@localhost:5432/tienda'
)

with engine.begin() as conn:
    conn.execute(text(
        'INSERT INTO clientes (nombre, ciudad) VALUES (:n, :c)'
    ), {'n': 'Ana López', 'c': 'CDMX'})

df = pd.read_sql('SELECT * FROM clientes LIMIT 10', engine)

CRUD relacional completo

# CREATE
conn.execute(
    'INSERT INTO productos (nombre, precio, stock) VALUES (?, ?, ?)',
    ('Laptop', 15999.99, 10)
)
conn.commit()

# READ
filas = conn.execute('SELECT * FROM productos WHERE stock > 0').fetchall()

# UPDATE
conn.execute(
    'UPDATE productos SET stock = stock - 1 WHERE producto_id = ?',
    (1,)
)
conn.commit()

# DELETE
conn.execute('DELETE FROM productos WHERE stock = 0')
conn.commit()

3. MongoDB (NoSQL documental)

Los datos se almacenan como documentos BSON (similar a JSON). Una colección agrupa documentos; no es obligatorio que todos tengan los mismos campos. 

# pip install pymongo
from pymongo import MongoClient

client = MongoClient('mongodb://localhost:27017/')
db = client['tienda']
productos = db['productos']

# CREATE
productos.insert_one({
    'nombre': 'Laptop',
    'precio': 15999.99,
    'stock': 10,
    'tags': ['electronica', 'oficina'],
    'specs': {'ram': '16GB', 'cpu': 'i7'}
})

# READ
for doc in productos.find({'precio': {'$gt': 10000}}):
    print(doc['nombre'], doc['precio'])

# UPDATE
productos.update_one(
    {'nombre': 'Laptop'},
    {'$inc': {'stock': -1}}
)

# DELETE
productos.delete_many({'stock': 0})

Agregaciones en MongoDB

pipeline = [
    {'$match': {'precio': {'$gte': 1000}}},
    {'$group': {
        '_id': '$categoria',
        'promedio': {'$avg': '$precio'},
        'total': {'$sum': 1}
    }},
    {'$sort': {'promedio': -1}}
]
resultados = list(productos.aggregate(pipeline))

4. Modelado documental vs relacional

  • Embebido: datos que se leen siempre juntos (dirección dentro del cliente).
  • Referenciado: datos compartidos o muy grandes (id de categoría en el producto).
// Embebido (buen para lectura conjunta)
{
  "nombre": "Ana",
  "direccion": {
    "calle": "Reforma 100",
    "ciudad": "CDMX",
    "cp": "06600"
  }
}

// Referenciado (evita duplicar catálogos grandes)
{
  "nombre": "Laptop",
  "categoria_id": ObjectId("...")
}

5. Criterios para elegir

  1. ¿Necesitas JOINs complejos e integridad fuerte? → Relacional.
  2. ¿El esquema cambia con frecuencia y los documentos son jerárquicos? → Documental.
  3. ¿Volumen masivo con acceso por clave simple? → Clave-valor / wide-column.
  4. ¿Relaciones densas tipo red social? → Grafo.
  5. ¿Analítica sobre históricos? → a menudo warehouse relacional o columnar (no solo OLTP).
💡 Arquitecturas modernas Es habitual combinar ambos mundos: OLTP relacional + caché + almacén documental o data lake para analítica. La decisión es por workload, no por moda.
