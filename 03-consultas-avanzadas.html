4.3 Consultas avanzadas y operaciones de manipulación de datos

Las consultas avanzadas permiten responder preguntas de negocio sin sacar todos los datos a la aplicación. Dominar JOINs, CTEs, funciones de ventana y transacciones es esencial en analítica y en backends robustos.

1. JOINs

-- INNER JOIN: solo coincidencias
SELECT c.nombre, p.pedido_id, p.fecha, p.total
FROM clientes c
INNER JOIN pedidos p ON c.cliente_id = p.cliente_id;

-- LEFT JOIN: todos los clientes, con o sin pedidos
SELECT c.nombre, COUNT(p.pedido_id) AS num_pedidos
FROM clientes c
LEFT JOIN pedidos p ON c.cliente_id = p.cliente_id
GROUP BY c.cliente_id, c.nombre;

-- Múltiples JOINs
SELECT c.nombre, pr.nombre AS producto, d.cantidad, d.precio_unit
FROM pedidos p
JOIN clientes c ON p.cliente_id = c.cliente_id
JOIN detalle_pedido d ON p.pedido_id = d.pedido_id
JOIN productos pr ON d.producto_id = pr.producto_id
WHERE p.fecha >= '2024-01-01';

2. Agregaciones y filtrado de grupos

SELECT
    ciudad,
    COUNT(*) AS clientes,
    AVG(total_gastado) AS promedio
FROM (
    SELECT c.ciudad, c.cliente_id, COALESCE(SUM(p.total), 0) AS total_gastado
    FROM clientes c
    LEFT JOIN pedidos p ON c.cliente_id = p.cliente_id
    GROUP BY c.ciudad, c.cliente_id
) t
GROUP BY ciudad
HAVING COUNT(*) >= 5
ORDER BY promedio DESC;

3. Subconsultas

-- Subconsulta escalar
SELECT nombre, precio
FROM productos
WHERE precio > (SELECT AVG(precio) FROM productos);

-- IN / EXISTS
SELECT nombre
FROM clientes
WHERE cliente_id IN (
    SELECT cliente_id FROM pedidos WHERE total > 5000
);

SELECT c.nombre
FROM clientes c
WHERE EXISTS (
    SELECT 1 FROM pedidos p
    WHERE p.cliente_id = c.cliente_id
      AND p.fecha >= CURRENT_DATE - INTERVAL '30 days'
);

4. Common Table Expressions (CTE)

Las CTE mejoran la legibilidad y permiten reutilizar subconsultas (incluyendo recursivas). 

WITH ventas_cliente AS (
    SELECT
        cliente_id,
        COUNT(*) AS num_pedidos,
        SUM(total) AS monto_total
    FROM pedidos
    GROUP BY cliente_id
),
top_clientes AS (
    SELECT *
    FROM ventas_cliente
    WHERE monto_total > 10000
)
SELECT c.nombre, t.num_pedidos, t.monto_total
FROM top_clientes t
JOIN clientes c ON c.cliente_id = t.cliente_id
ORDER BY t.monto_total DESC;

5. Funciones de ventana (Window Functions)

SELECT
    cliente_id,
    pedido_id,
    fecha,
    total,
    SUM(total) OVER (
        PARTITION BY cliente_id
        ORDER BY fecha
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS acumulado,
    RANK() OVER (
        PARTITION BY DATE_TRUNC('month', fecha)
        ORDER BY total DESC
    ) AS ranking_mes,
    LAG(total) OVER (
        PARTITION BY cliente_id ORDER BY fecha
    ) AS total_anterior
FROM pedidos;
Función Uso típico
ROW_NUMBER(), RANK(), DENSE_RANK() Rankings y top-N por grupo
LAG / LEAD Comparar con fila anterior/siguiente
SUM/AVG/... OVER Totales móviles, acumulados
NTILE(k) Segmentar en percentiles / buckets

6. Manipulación de datos (DML) y transacciones

BEGIN;

UPDATE productos
SET stock = stock - 2
WHERE producto_id = 10 AND stock >= 2;

INSERT INTO detalle_pedido (pedido_id, producto_id, cantidad, precio_unit)
VALUES (1001, 10, 2, 499.99);

UPDATE pedidos
SET total = (
    SELECT SUM(cantidad * precio_unit)
    FROM detalle_pedido
    WHERE pedido_id = 1001
)
WHERE pedido_id = 1001;

COMMIT;  -- o ROLLBACK si algo falla
⚠️ ACID Las transacciones garantizan Atomicidad, Consistencia, Aislamiento y Durabilidad. En operaciones que afectan varias tablas (pedido + stock + detalle), usa siempre transacción explícita.

8. Análisis de rendimiento

EXPLAIN ANALYZE
SELECT c.nombre, SUM(p.total)
FROM clientes c
JOIN pedidos p ON c.cliente_id = p.cliente_id
WHERE p.fecha >= '2024-01-01'
GROUP BY c.nombre;
  • Busca Seq Scan en tablas grandes cuando esperabas Index Scan.
  • Revisa estimaciones de filas vs filas reales (estadísticas desactualizadas → ANALYZE).
  • Evita funciones sobre columnas indexadas en el WHERE (WHERE YEAR(fecha)=2024 impide usar índice; mejor rango de fechas).

9. Buenas prácticas de seguridad

  • Nunca concatenes input de usuario en SQL (inyección). Usa parámetros / placeholders.
  • Principio de mínimo privilegio: usuarios de la app con permisos solo a lo necesario.
  • Cifrado en tránsito (TLS) y en reposo cuando haya datos sensibles.
  • Auditoría de accesos y cambios en tablas críticas.
# Seguro (parametrizado)
cursor.execute(
    'SELECT * FROM clientes WHERE email = %s',
    (email_usuario,)
)

# INSEGURO — no lo hagas
cursor.execute(
    f"SELECT * FROM clientes WHERE email = '{email_usuario}'"
)
